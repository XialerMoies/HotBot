# 前端整改与验收记录

本轮针对页面职责混杂、文章列表依赖当前事件、无反馈按钮、空白问答和失实入口进行整改。此记录描述已实现功能，不代表整个毕设规划已完成。

## 页面和组件

- Vue Router 哈希路由：工作台、事件、文章、问答、工作区、任务监控。栏目刷新仍保留，支持浏览器前进后退。
- App 只承载导航和共享资源；页面分别负责业务交互；事件详情、工作区表单分别拆为业务组件。
- 复用 Reka UI 的 Primitive、Dialog、AlertDialog、Tabs 和 Lucide 图标。表格、输入使用原生语义控件。没有引入第二套视觉组件库。
- 统一 Button、PageHeader、Panel、EmptyState、RequestState、SourceLink、Pager；统一日期、状态文案和安全原文链接。
- 移除实际跳到任务监控的“系统设置”；刷新明确表示重新读取任务记录，不能假装触发采集。

## 已修正的功能

- 文章库读取全部保存的文章，独立搜索、来源过滤、分页并跳转对应事件；不存在链接时显示“未提供”，不生成 # 假链接。
- 事件列表按更新时间排序，搜索实体/标题并过滤状态；URL 带事件编号，详情含时间线、原文和问答入口。
- 不再把后端启发式 confidence 当作真实“匹配度百分比”展示。
- 问答选择范围明确，支持问题预填、禁用空提交、加载与错误提示；切换事件取消请求，并拒绝旧结果覆盖新事件。
- 回答与证据并排展示，证据片段可追溯至原文。模型正文为空时后端使用原文降级，不展示空白成功结果。
- 工作区分为关注、订阅、提醒和每日摘要四个 Reka 标签页。添加/删除有反馈；订阅支持真实暂停、恢复和删除；删除通过库提供的确认弹窗。
- 新增 GET /api/events/articles、PATCH /api/workspace/subscriptions/{id}、DELETE /api/workspace/subscriptions/{id}。
- 工作区请求失败保留原数据和表单输入，按钮忙时不能重复提交；跨账号返回结果不会覆盖当前工作区。

## 验证

- 前端 npm test：6 项通过，覆盖 Button 单击/禁用、异步旧结果、全部文章过滤、无效链接、问答切换、订阅失败和恢复。
- Java mvn test：129 项通过；覆盖新增文章库、订阅持久化及跨工作区边界、空模型结果降级。
- Python evidence 专项：3 项通过。
- npm run build：通过。
- 实际浏览器验证：桌面工作台、事件筛选、文章读取（验收时 62 篇）、问答请求、登录、工作区标签切换、订阅添加和暂停；后端重启后登录和订阅数据仍保留。
- 独立本地验收账号验证：关注添加/移除、订阅添加/暂停/恢复/删除、生成摘要。测试订阅已清理，没有修改其他账号。
- 任务页在 1920、1440、1024、768、390、320 CSS 像素视口没有页面级横向溢出；窄屏表格在容器内滚动。390px 问答页无横向溢出，移动导航使用库提供的模态抽屉。
- CSS 断点会随浏览器缩放后的有效宽度调整；尚未逐项覆盖所有物理分辨率、操作系统 DPI 和浏览器缩放倍率，不能承诺像素完全一致。

## 当前限制

- 采集源仍包含非科技资讯，历史库含测试/重复事件；本轮未删除或伪造这些数据。
- 工作区仍采用原有 JSON 持久化及 token 方案，不等同于规划的数据库、Spring Security/JWT。
- 任务页只监控已有采集源；手动触发采集、任务队列和运行历史不是已完成能力。
- 摘要与提醒仍沿用现有匹配机制，效果依赖后端事件和原文质量。
- 没有把当前后端的 claims 字段当作独立验证后的事实准确率展示；引用来源本身不证明大模型结论已通过事实核验。
