# 真实证据链与问答闭环验收记录

验证日期：2026-09-27。范围：本轮正文、片段检索、引用、问答与降级改动；不代表毕业设计整体验收。

## 已实现

- ML 服务提供公开网页正文提取，识别 article、articleBody、常用博客正文容器，排除脚本、导航、页脚和广告区域。未找到正文时返回显式状态，不把整个页面、标题或 Hacker News 热度当成正文。
- 抓取只允许公网 HTTP(S) 的标准端口；每次跳转重新验证地址。连接固定到已经检查的公网 IP，HTTPS 保留原域名 SNI 和证书校验。响应大小上限 2 MB；连接后由独立计时器中断慢速响应头/正文，整条跳转链共享 8 秒预算。
- Java 按需抓取每个事件最多两篇缺少正文的报道，成功正文持久化，失败结果缓存 10 分钟后允许重试。既有事件 ID 和归类不变。
- 事件内按问题匹配证据，片段最多 800 个 UTF-16 代码单元、步长 650，最多返回 8 段；先为不同文章保留位置。BODY、SUMMARY、EXCERPT 明确区分。
- 每段证据带文章 ID、原链接、原始采集来源、字段类型、内容标识及起止偏移。偏移指向已保存的清洗文本字段，不是原始网页 HTML。
- 模型返回结构化 claims，每条结论须引用已知证据 ID。Python 与 Java 分别验证引用结构；前端展示的 URL 和片段由服务端保留，模型不能覆盖。
- 空证据不调用模型。模型失败、空输出、结构错误、伪造引用时展示检索片段并标注降级，不伪装成完整分析结论。
- 回答引用按钮定位并突出证据；工作台时间线节点定位来源卡片；提供原文链接和正文/摘要标记。游客沿用登录入口。
- 状态接口只说明 ML 进程可达性及 NER 状态，生成能力标为 UNVERIFIED；是否生成成功以每次实际问答为准。

## 接口与数据

| 接口 | 用途 |
| --- | --- |
| ML `POST /api/articles/content` | 输入 `{url}`，输出 `{body,status,url}` |
| Java `GET /api/evidence/events/{eventId}/sources` | 按需抓取并返回现有事件文章，包含 contentStatus/contentFetchedAt/fullBody |
| Java `POST /api/evidence/events/{eventId}/answer` | 输入 `{question}`；输出 answer、claims、evidence、fallback |
| Java `GET /api/evidence/status` | reachable、ner、generation、checkedAt |

来源读取接口会更新正文缓存。BODY 抓取成功；NO_ARTICLE_BODY 无可识别正文；FETCH_FAILED/FETCH_UNAVAILABLE 抓取失败或服务不可达；URL_REJECTED 地址不允许；UNSUPPORTED_CONTENT 非 HTML；SIZE_OR_TIME_LIMIT 超限；REDIRECT_LIMIT 跳转过多。失败不会生成虚假正文。

## 明确边界与后续工作

1. 引用验证证明引用 ID 有效、片段及链接可追溯，不证明结论被片段语义支持或原报道真实。尚未进行人工标注的事实准确率、引用准确率及对比实验。
2. 当前证据检索为事件内词法匹配与通用问题回退，尚未实现证据级向量检索/重排序；具体跨语言问题可能检索不足。每次最多抓取两篇，更多报道需后续请求；概述问题并不覆盖长文所有内容。
3. 登录限制仍主要由前端控制，已有证据 API 未新增服务端鉴权；公开部署前须与认证、令牌生命周期、权限控制和速率限制一起落实。
4. 正文依赖网页结构和网络，不绕过登录/付费墙，不保证全站抓取。正文缓存暂未自动检测源页面更新，模型/提示词版本还未完整审计落库。
5. socket deadline 约束已建立连接的响应读取；系统 DNS 解析仍依赖操作系统解析超时。仍需进行并发、DNS 卡住、长期运行及资源占用测试。HTTPS 握手和 DNS 等边界不可按本轮慢速正文测试推断为完全验证。
6. 成功恢复 Embedding/NER 服务，不等于对所有历史文章做完向量与实体补算。本轮未批量改写生产事件的向量特征。
7. 生产仍使用 JSON 持久化，关系数据库、专用密码哈希、自动更新提醒及毕业设计评测交付仍按规划推进。

本轮可以作为“可追溯问答工程闭环”的功能验收记录，不能作为完整论文实验或生产安全验收报告。
