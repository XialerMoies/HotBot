# 科技采集范围与历史数据隔离

日期：2026-09-27。范围：数据质量治理，不调整页面样式、聚类评分或个人订阅。

## 当前策略

- 默认 `bot.news.tech-only: true`，采集前检查 `enabled` 和 `category: tech`。
- 保留现有 36氪、环球科学、Hacker News 配置；默认停用新华社综合、环球时报、中国国家地理、知乎日报。
- 来源标记为科技不意味着每篇文章都会通过。`NewsContentPolicy` 对标题、摘要、正文摘录应用 `tech-scope-v1` 规则，先排除测试与促销，再检查来源链接及科技信号。不使用来源名称、URL 或标签作为科技证据。
- 覆盖人工智能、软件开发、芯片、计算基础设施、网络安全、机器人、量子计算、航天、能源及部分生物技术；一般时政、生活、体育、军事行动与没有足够科技信号的内容不收录。
- 明确的征订、广告标记、扫码购买、限时优惠优先排除。产品性能测试、技术领域的订阅服务发布不会因为单独出现“测试”“订阅”被排除。
- 缺少来源名称或 HTTP(S) 链接不入库；localhost、示例域名及明确测试标题隔离。链接检查仅验证基本格式，不代表原文真实性已经核验。
- RSS 最多检查 30 条候选，再过滤、去重、计算特征；保留既有总结果数上限。被过滤内容不会进入 Embedding 或公开事件库。
- 生产事件服务也执行校验。`POST /api/events/cluster/news` 拒绝不合规文章并返回 400 与原因码。无来源文章的原始向量聚类请求不能直接创建生产事件，应使用附带来源的文章入口。算法单元测试仍在临时目录运行。

## 隔离与持久化

`EventDataMaintenance` 在生产事件服务读取存档前运行，也可通过命令行预览。每次实际隔离保存：

1. `events.backup.json`：原存档逐字节完整备份。
2. `quarantine.json`：原因码和完整事件对象，包括文章、时间线、向量及实体。
3. `manifest.json`：时间、策略版本、路径、保留数、隔离数及原因统计。

路径在 `bot-server/storage/quarantine/scope-*`，已加入 Git 忽略规则。不在首页、文章库、事件详情和事件问答的证据集合中提供隔离内容。

采用整事件隔离：如果一个聚类有不合规文章、缺失关联文章或悬空时间线，整组留待复核，不自动重建时间线、修改事件 ID 或拆散证据链。多个事件重复持有同一文章 ID 时保留首次出现的合规组，后续组隔离。不同 ID 的近似报道不在本次清理中自动合并。

先完成归档，再原子替换生产存档；归档失败、文件损坏或维护期间文件变化时中止。运行中的后端必须停止后才能从命令行执行实际清理，以免旧内存覆盖存档。启动清理发生在提供服务之前。禁止同时启动多个写入同一文件的后端实例。

测试污染根因也已修复：旧 `DailyBotScheduler` 兼容构造器会创建独立持久化事件服务，单元测试因此曾写入真实 `storage/events.json`。现在兼容构造器不再拥有事件存储，Spring 使用注入的单例；Surefire 默认把事件与工作区状态指向 `target/test-storage`，专项测试使用临时目录。

## 运维命令与恢复

在 `bot-server` 目录执行（PowerShell）：

```powershell
mvn -q -DskipTests compile dependency:build-classpath '-Dmdep.outputFile=target/runtime-classpath.txt'
$scopeClasspath = 'target/classes;' + (Get-Content target/runtime-classpath.txt -Raw)
# 预览不修改文件
java -cp $scopeClasspath com.bot.service.EventDataMaintenance storage/events.json
# 先停止后端并确认没有其他写入进程，再实际执行
java -cp $scopeClasspath com.bot.service.EventDataMaintenance storage/events.json --apply
```

恢复前先停止后端，备份当前存档，然后从隔离目录提取需要恢复的完整 cluster；先核对来源、证据和事件 ID，再调整误判规则或纠正文章元数据，通过离线预览后恢复。直接恢复原始脏备份会在下次启动时再次被同一策略隔离，不能以复制备份绕过准入规则。完整备份可用于离线审计，不建议直接回滚在线数据。
